# Design

## Command Contract

- `migrate <change> --dry-run` reports legacy sources, archive destinations,
  generated structured paths, and whether the workspace is already migrated.
- `migrate <change> --apply` performs the same deterministic upgrade.
- `--expected-plan-sha256` is removed because no accepted-plan protocol remains.
- The command assumes one writer for a change workspace. Concurrent migration or
  concurrent edits are unsupported; no lock or cross-process guarantee is
  provided.

Successful JSON contains only:

| Field | Meaning |
|---|---|
| `mode` | `dry-run` or `applied` |
| `change_id` | selected change |
| `legacy_sources` | recognized source/archive path states, in review-log/timeline/tasks order |
| `generated_paths` | lexically sorted relative paths considered by this run |
| `already_migrated` | true when archive exists and no top-level legacy source remains |

Usage and root-selection errors return 2. Invalid input, path conflicts, and I/O
failures return 1. Success returns 0.

Each `legacy_sources` entry contains exactly `path`, `archive_path`,
`target_directory`, `source_state`, and `archive_state`. State values are
`present` or `absent`.

## Source And Destination Rules

The recognized legacy inputs remain `review-log.md`, `timeline.md`, and
`tasks.md`. For each input:

- source only: archive it;
- source and archive with identical bytes: continue;
- source and archive with different bytes: fail before removing the source;
- archive only, while another top-level source remains: use it as preserved
  input while finishing the active migration;
- neither: ignore that artifact.

Migration requires `proposal.md` and at least one recognized source or archived
legacy artifact. It never interprets or splits legacy content.

Recognized inputs and archive destinations must be regular files, not
directories or symlinks. Legacy bytes are opaque and may be non-UTF-8. Markdown
files that need front-matter or index updates must be valid UTF-8.

If no top-level legacy source remains and at least one recognized archive file
exists, the workspace is already migrated: dry-run reports it and apply is a
no-op. It does not regenerate, merge, validate hashes for, or overwrite README,
indexes, provenance, reviews, tasks, or other later edits.

When any top-level legacy source remains, generated destinations have two
explicit classes:

- transform in place: `README.md`, existing `proposal.md`, `requirements.md`,
  `research.md`, `terminology.md`, `design.md`, `plan.md`,
  `execution-map.md`, `specs/README.md`, and existing `specs/*.md`; derive the
  result from the current UTF-8 text with idempotent front-matter/status helpers;
- create if missing: `decisions/README.md`,
  `decisions/DR-001-migration-provenance.md`, `reviews/README.md`, and
  `tasks/README.md`; accept an existing regular file only when it equals the
  deterministic generated bytes, otherwise fail before source removal.

A directory or symlink at one of these file paths is a conflict. This ownership
list is also the complete source for `generated_paths`.

## Write Order And Recovery

1. Preflight every source/archive pair and every generated destination under
   the single-writer assumption.
2. Write missing archives atomically.
3. Write or update deterministic structured indexes atomically.
4. Remove only top-level legacy files whose bytes match their archive.
5. Return the resulting filesystem plan.

All expected conflicts are detected before source removal. Process interruption
can leave only additive archive or scaffold files; rerunning completes the same
operation while a top-level source remains. Once all top-level sources are
removed, repeat apply is a no-op and preserves subsequent edits. Git remains the
user-level inspection and rollback mechanism.

## Validation

Validators infer structured mode from structured markers. They validate current
workspace structure and report legacy top-level artifacts, but do not parse
migration transactions, bootstrap registries, provenance hashes, or frozen
legacy review rounds.

Historical `.changes/.control/` migration files are inert data and may be
removed from Core's own change history without affecting workspace validity.

## Compatibility

- Preserve exact legacy bytes in `.changes/archive/<change>/legacy/`.
- Preserve dry-run and apply modes.
- Intentionally remove the unpublished expected-plan digest contract.
- Keep generated README/index/provenance locations stable.
- Keep Node/Python output fields and errors aligned.

## Input State Matrix

| Top-level source | Archive | Apply behavior |
|---|---|---|
| present | absent | archive, scaffold, then remove source |
| present | identical | scaffold, then remove source |
| present | different | fail; leave source untouched |
| absent | present, with another source still present | use archive for provenance; finish active migration |
| absent for all recognized paths | at least one present | no-op as already migrated |
| absent | absent for all recognized paths | fail; not a migration candidate |

Generated directories or symlinks where regular files are expected are
conflicts. Node and Python use the same matrix, JSON fields, and exit classes.
